`kenBurns()` (on `@glissade/scene/motion`) — the classic photo pan/zoom as a one-call, PURE track-emitting motion preset. `kenBurns(node, opts?)` bakes a `<id>/scale` (the zoom) + optional `<id>/position` (the pan) vec2 keyframe pair onto an EXISTING node's own transform ids and returns `{ tracks, end }` — you inject them with `tl.tracks([...])` (or spread into a timeline's `tracks`). It creates NO node: the target already lives in the scene; it just reads/writes `scale` + `position` (Image or Rect alike — an Image draws centered so a scale zooms about center + position pans).

Signature: `kenBurns(target: Node, opts?: { zoom?: number | [from, to]; pan?: [dx, dy] | { from, to }; duration?; ease?; at? }): { tracks: Track[]; end: number }`. `zoom` defaults `[1, 1.1]` (a gentle push-in); a bare number `N` means `[staticCurrentScale, N]` (uniform on both axes); a tuple is explicit both ends (push-in OR pull-out). `pan` defaults to none (zoom-only is valid); `[dx, dy]` is an offset drift (`from` = static position, `to` = `from + [dx, dy]`); `{ from, to }` is explicit endpoints. `duration` defaults `5`s (tracks run `[at, at + duration]`), `ease` defaults `'easeInOutSine'`, `at` defaults `0`. Missing `id` fails loud (`KenBurnsError`).

Determinism pin: a DEFAULTED `from` reads the target's STATIC constructed prop (`target.scale()` / `target.position()` as the node was built), NEVER the node's animated state at `at` — it does not evaluate the node's other tracks or the timeline at emission. So the emitted tracks are a pure function of (static props, args) and are ORDER-INDEPENDENT (emit before or after other tracks alike). If you've also authored a scale/position track on the node, pass an explicit `from`. Cross-referenced with `camera()` in the describe() summary — kenBurns is the per-NODE one-liner; `camera()` is the whole-scene rig with layered parallax.
